# CLAUDE.md

Guidance for Claude Code in this repository.

## What this is

A small WebXR garden outside one of the hallway's doors (three.js 0.186, plain ES modules, no
bundler or build step): a lawn, a stream under a foot bridge into a pond, a trail to a bench, and a
book on the bench to read, with vrlbry's book controls (AriaMoKr/vrlbry, a checkout at `../vrlbry`:
its toolbar, contents, text sizes, themes, one page or two, distance and size, links and Back, and
text view). It is a place behind a door of the Hallway (https://ariamokr.github.io/hallway/,
AriaMoKr/hallway, a checkout at `../hallway`), whose conventions and controls it follows; much of
its code is the hallway's (said so at the top of each such file). `public/` is the whole site.
It works with a TV's remote in the hallway's Android TV app (AriaMoKr/HallwayApp, a checkout at
`../HallwayApp`: the site in a full-screen WebView whose user agent ends ` HallwayTV/<version>`).
`README.md` covers using it (on a TV too), what it does with the hallway's door link, the hallway's
door entry for here (its fourth door, since the hallway's `9dd2d5a`), and the pictures either side
of that door.
The user asked for the hallway to be left alone, so change `../hallway` only when asked.

Meant to publish at https://ariamokr.github.io/outside/ from `main` of AriaMoKr/outside by
`.github/workflows/pages.yml` (same origin as the hallway, so the VR hand-over works).

## Commands

```bash
npm install                  # postinstall: common's tools/vendor.mjs copies what vendor.json lists (three, common, layersharedsession, Trystero, and IWER) into public/vendor/ (gitignored)
npm start                    # tools/serve.mjs (common's, on port 8090): public/ on http://localhost:8090/ (IPv6 only on Windows; for a Quest: npm start -- --host 127.0.0.1)
npm test                     # node --test "test/*.test.js", tsc's two checks among them (test/types.test.js)
npm run types                # tsc -p tsconfig.json, then -p tsconfig.strict.json, alone
node tools/preview.mjs       # public/hallway-preview.jpg, the garden for the hallway's doorway (headless Chrome)
node tools/hallway-view.mjs  # public/views/, the hall seen out of its door to here, from a copy of ../hallway (the door added if it has none)
```

Node 22 or newer (`engines`; common's `tools/chrome.mjs` needs its built-in WebSocket); CI runs Node 24 (common's Pages workflow). It runs under MSYS2 UCRT64 here (`MSYSTEM=UCRT64 /c/msys64/usr/bin/bash -lc 'cd /c/git/my/claude/outside && …'`).

## Layout

- `garden.js`: pure (no three, tested in Node). Where everything is (`GARDEN`, `DOOR`, `HOUSE`, `PANEL`, `BENCH`, `SEAT`, `BOOK`, `BRIDGE`, `TRAIL`, `TREES`), the stream (`streamAt`, the widths, `waterLevel`), the ground (`terrain`, sampled once on `GRID` by `layoutGarden`; `groundAt` reads the grid, and the deck on the bridge), what is on top for a visitor's ring (`surfaceAt`: the ground, or the water over its very edge), walking (`clampWalk`: hedges, wall, house but the doorway, trunks, bench, the bridge's rails, the water; `standable`), the way (`route`: straight when clear, else A* on the grid, corners cut), `doorCrossed`, `doorSpawn`, `castRay` (what a pointer meets: door, panel, wall, book, bench, tree, hedge, wall, water, ground; the ground by marching the grid). Its types: `Layout` (layoutGarden's, which scene.js, house.js and controls.js take), `Place` ({ x, z, yaw }), and `RayHit`, what castRay writes into (it is generic over the hit, as common's is, so controls.js's `GardenHit` comes back as itself). Coordinates: metres, the house's wall at z = 0, the garden along -z, the door at x = 0, yaw 0 faces -z.
- The door contract is AriaMoKr/common's `door.js` (`common/door.js` in the import map and in Node): the hallway's door link (`readVisit`), the way back (`wayBack(search, OUTSIDE_ID, { origin })`, `keptWay`, `leaveUrl`), the address cleaned (`withoutVisit`), where the hallway's view of its door to here is (`hallwayViews(way, OUTSIDE_ID)`, `viewParams`). `way.js` keeps what is this garden's: `OUTSIDE_ID`, `DEFAULT_GLOW`, and `HALLWAY_DOOR`, the hallway's door entry for here (kept in step with README's).
- `pages.js`: pure. The book set in pages (`paginate`, with a `measure(text, font)` function and a text size, `scale`: vrlbry's `FONT_STEPS`, `typeAt`; the contents and the sources run over onto more pages when they must), spreads (`spreadPages`, `spreadOf`, `sideOf`), and every line's place in the book, `at` = [section, block, word] (`SECTION`: the title page, the contents, each piece, the sources; the paragraph, stanza, entry or note, -1 for a heading; the words of the block before it), a page's `at` its first line's: `pageAt` finds a place's page at any size, which is how the reader stays at the same words. The contents page's entries are links (`page.links`, `linkAt`). The open pages' words for a screen reader (`readingText`: the lines put back into headings, paragraphs, stanzas and the contents' list (`ReadingBlock`, a type per kind), from the `start`, `carried`, `spoken` and page `kind` marks `paginate` leaves; `spreadLabel`), and each part as blocks for the text view (`sectionBlocks`, numbered as `at` numbers them). Its types: `Page` (its `Item`s, each a `TextItem` or a `RuleItem`, told apart by `'rule' in it`, since tsc without `strict` doesn't narrow on `it.rule`; its `Link`s), `At`, `Font` and `TypeName` (`TYPE`'s), what `paginate` takes (`BookText`, `Piece`, `Measure`; reading.js's `PIECES` are `Piece`s, so tsc checks the text against it), `ReadingBlock` and `SectionBlock`. `book.onShow` says the pages are open (on opening, as a page turns, at another size); `overlay.showBookText` puts their words in a visually hidden, politely live region named for the book (not while the text view shows them). `reading.js`: the book's text (public domain, sources named; check a change against them).
- `book.js`: the book closed on the bench and open in front of the reader (pages painted when first needed in the reader's theme and kept while near the spread open, or in the one a turn goes to, `_page`; the leaf turning over, a page at a time sliding across with only its half of the book shown once still), read with vrlbry's controls: the toolbar under the pages and the contents beside or over them (canvas panels, `canvas-panel.js`: vrlbry's `ui/panel.js` Panel, cut down), `changeFont` (set again, at the same words; steps one after another keep to the words the first started from), `setTheme`/`cycleTheme`, `togglePages`/`setSingle`, `adjustDistance`/`adjustScale`, `grab`/`release` (a VR grip), `toFront`, the contents page's links with a trail (`followLink`, `goBack`, `backTo`, `back`), `jumpToPlace` (the text view's), and `pick`/`setHover`/`press` for every pointer (a `BookHit`: one of its panels or a page; controls.js's `GardenHit` has its fields). On a screen `_fit` places it so the pages and the toolbar fill the view above a strip at its foot (corners projected: the pages' curve and the toolbar come nearer than the book's middle); in VR it is held where it was last (`settings.readDistance`). Its `pages` are none (`[]`) and its `camera` null until it is first opened. `reader.js` (pure): vrlbry's themes (`THEMES`; the text view's CSS has the same colours, tested), `singlePage`/`pageViewSetting`, `fontStep`, `READ`'s limits, and `readerSettings`, the reader's choices as stored (`ReaderSettings`, with a `ThemeName` and a `PageView`; `outside.book` in localStorage, main.js; this site's own). `text-view.js`: vrlbry's text view (`ui/text-view.js`), here the book's parts (the title page with the contents, a piece, the sources: `renderPart`, pure and tested with vrlbry's fake DOM), keeping its place with the 3D book to the word (`wordStarts`, `firstWordBelow`, `_topBlock`, `_sync`; a link in the title page's contents, a part, or a piece from the view's own contents goes to the piece's start, `_aim`, since a spread can begin with the end of the piece before; `_scrollTo` measures the toolbar itself, since its observer hasn't run when the view has just been shown, and opening checks the place again on the next frame). Its class is `tv-view` (style.css's rules for it and its themes), as vrlbry's has been since its `0516bf4`: `tv` is TV mode's, on `<html>`, where a rule on `.tv` alone reached the whole TV page (the card's link in the view's blue, `<html>` fixed on paper), so a test keeps every rule on `.tv` to `html.tv`. The browser's Back along the links, then putting the book down, is common's `back-history.js` (an entry when it opens and per link, taken back out when it is put down otherwise), with `prefix: 'outside'`: its fields keep the names this site's own copy gave them (`outsideBook`…), so entries already in visitors' tabs are still the book's.
- The TV (common's `tv.js`, `tvMode()`: the app's user agent, or `?tv=emulate`): `html.tv` (style.css's 10-foot view: the card, the hint and the text view), every lighter version (`lite.js`, below) for the frame rate, `TV_PITCH` (`controls.restPitch`: the view rests tipped down so the dot can land on the bench), `controls.aimMiddle` (the dot while walking: `openBook` clears it, since reading OK is the book's, and `closeBook` sets it again), and common's `Remote` (main.js, root `document.body`, `first`: `overlay.bookTools` while reading, so Menu lands on the book's buttons; `openBook` calls `remote.forget()` (common v0.6.2), so that holds after the card was used; Sit on the bench and Read the book in the card `remote.walk()` first, so the arrows act at once): OK is `useMiddle` (reading: the book's `enter`, opening the contents; seated: the book; else `controls.useMiddle()`), Back is `stepBack`, from `remote.js`'s `backStep` (pure, tested): the text view's contents, the text view, the book's contents, then the book and its links, which are left to the app's Back through `BackHistory`'s entries (`step()` false) unless the book has none (`bookEntry`: `navigator.userActivation.hasBeenActive` when it came out; common's README, "Back and the page's history"), then up from the bench. The card has the book's keys as buttons while reading (`overlay.bookTools`, `onBook`, kept in step by `setBook`), the hint the remote's (`TV`: walk, sit, read, text, card, cardReading; `setInCard`, `setTextView`, `setSeated`), and the invite as text (`inviteText`). In the text view on a TV the focus stays on the view: ↑ ↓ are `textView.scrollStep`, ← → `textView.turn`, and while it is open CSS hides what it covers so the remote's stops are its own. Common's controls read keys through `keyOf` (OK and the spare keys come with no `code`; with TalkBack on, channel and media keys stand for the arrows) and leave alone a key already used (`defaultPrevented`: the remote's OK).
- `scene.js` builds everything as a few merged meshes with light baked into vertex colours (`bake.js`: a low sun traced through the occluders it is given, crowns letting some through by the leaf crossed; sky light; point lights. Its types: `Occluder`, an ellipsoid, a cylinder or a box, opaque without a `density`, and `Prepared`, one with the bounding sphere `prepare` gives it; `Light`, and `Env`, what lights the garden (scene.js's `env`), each colour an `RGB`, three numbers (so water.js can spread the sun's and the sky's into `THREE.Color`s; scene.js's `lin` and `scale` make them). `bake` takes anything with a Builder's fields and returns it as its own type). It calls `plants.js` (trees, hedges, grass/flowers/reeds, the willow's strands), `features.js` (bridge, bench, dry-stone wall, rocks, lily pads, water-gates), `house.js` (the wall, windows, roof, doorcase, the sign and plaque, the panel, the portal), `water.js` (the stream and pond, one ribbon, its shader; with `rippleMap` (lite's `water`), its ripples read from `rippleTexture`, a tileable picture of the same noise with its slope, `RIPPLE`, `rippleData`, under `RIPPLE_MAP`: worked out per pixel they cost the water four or five times as much), and common's `sky.js` (`skyTexture`: the sky painted once, equirectangular; `skyDome` looks it up by direction; the water reflects it through `SKY_UV`, and `bake.js` lights by its `SUN_DIR`). The garden's sky is common's: every window behind every door shows it, so a change to it is made in common (its `src/sky.js`, then a new tag here), never in a copy here. `builder.js` is the hallway's Builder with cuboids, cylinders, lumpy spheres and triangles added. Grass and strands sway in a vertex shader (`sway` attribute). The water, the ground and the sky dome draw after everything else (`renderOrder` 1, 2, 3; three.js otherwise sorts opaque meshes by material, and those made early draw first, before what hides them, so the GPU's early depth test skips none of their pixels): the same picture, since the dome (radius 90) lies beyond the meadow's farthest point (about 83 m).
- Drawn lighter (`lite.js`, pure: `LITE`, `liteParts(search, tv)`): a TV has every lighter version, any browser those `?lite=` names (a list, or `all`), to see that it still looks right. `ratio` and `filter` are main.js's (`LITE_PIXEL_RATIO` 1, `LITE_ANISOTROPY` 2), `card` its `lite-card` class on `<html>` (style.css: no blur behind the card), and `water` and `ground` `buildGarden`'s `lite` option: `buildWater`'s `rippleMap`, and the terrain's `GROUND_LITE` (the path and mud read only where their splat is, with `textureGrad` and derivatives taken outside the branch; the grass's large-scale variation once a vertex, `textureLod`). README's "The TV app" has what each part cost on this computer and the table before and after. They were measured with the GPU's timer (`EXT_disjoint_timer_query_webgl2`) around renders into a fixed 960 × 540 target (twice that for a pixel ratio of 2, 4× MSAA as the canvas has) through a camera of its own at the viewer's pose, the page's animation loop stopped, the cases taking turns in one burst after a warm-up (a laptop's GPU clocks down whenever it idles), and the fastest of 15 rounds; a part's own cost as K copies of it (shared geometry and material) drawn at once, less an empty draw. A hidden browser pane's window is 0 × 0 (the camera's aspect NaN, nothing drawn) until `resize_window` gives it a size.
- The doorway's shader is common's `portal.js` (`portalMaterial`, `placePortal`, and `setView` for a picture hung by views.json's parameters), which `house.js` uses. `textures.js`: canvas textures, seeded; its painters take a new `canvas`'s `getContext('2d')` as never null (a cast, as common's `sky.js` has).
- `controls.js`: the garden's subclass of common's `Controls` (`common/controls.js`, whose README, "controls.js", says what each device does and what a site gives it, and whose tests cover it), as the hallway's and the rooms' are. Common's is the walking on every device: a drag to look, keys through `tv.js`'s `keyOf` (a TV remote's come with no `code`; with TalkBack on, channel and media keys stand for the arrows; a key a page control has used (`defaultPrevented`: the remote's OK), or one in a form control or a `data-own-keys` element, is the page's, and so are Space and Enter on a button), a click or a tap (two fingers neither look nor tap), a gamepad (`gamepad.js`), and in VR the trigger, a grip and the sticks as common's `nav.js` says (`hallway.nav` in localStorage, shared with the hallway: move smooth or teleport, turn snap or smooth); `walkTo(x, z, { face, then })` (walking or looking, a drag too, ends it), `onDoor(how, hit)` on the doorway, `reduceMotion` (a walk jumps to its end), `setEyeLift` (seated mode), `moveSpeed`/`turnRate` (the vignette), `aimMiddle` and `useMiddle()` (a gamepad's A, the remote's OK), `onTeleport`; nothing allocated per frame. ## Conventions

- Client URLs stay relative (tested). Quest 3 is the performance target, and a TV in the hallway's app (a Mali-G52: 60 fps needs the lighter versions, `lite.js`; HallwayApp's `tools/tv-check.mjs --url` measures it, a debug build at a dev server over adb reverse): few draw calls (about 15; the open book adds three: its two halves, each its board and the pages under it merged, and the toolbar), light baked, nothing allocated per frame in controls/castRay/the book's pick and hover/the frame loop (a panel is redrawn only when what it shows changes). Build time is ~350 ms; keep it well inside the ~5 s a VR grant lasts.
- Types, with no build: `tsconfig.json` checks `public/js/` from its JSDoc, as the template's and the hallway's do (`allowJs`, `checkJs`, `noEmit`; `moduleResolution` `bundler`: three's types from `@types/three`, common's and the layer's from their `.d.ts`; `lib` ES2023 (pages.js's `findLast`), DOM and DOM.Iterable; `types: []`). The page is served unchanged and the import map stays. `test/types.test.js` runs tsc, so `npm test` and the Pages workflow do, and fails rather than skips without TypeScript (devDependencies: `typescript` 5.9.3, `@types/three` 0.186.0). What TypeScript's DOM library leaves out (WebKit's fullscreen names, `window.outsideXrGranted`, `window.__outside`) is in `types/globals.d.ts`, never served. `strict` comes a file at a time, as in the template: `tsconfig.strict.json` (it, with `strict` on) includes only the files that pass it, `bake.js`, `book.js`, `builder.js`, `canvas-panel.js`, `controls.js`, `garden.js`, `lite.js`, `pages.js`, `panel.js`, `preview.js`, `reader.js`, `reading.js`, `remote.js`, `text-view.js`, `textures.js`, `together.js`, `water.js` and `way.js` so far, and `test/types.test.js` runs it too. A file joins its `include` when a change makes it pass; what an included file imports is checked strictly with it, and so is a file its JSDoc names a type from (`import('./book.js').Book`). So `features.js` (54), `house.js` (20), `overlay.js` (55) and `plants.js` (77) wait only for their own. With `strict` all of `public/js/` has 300, nearly all parameters and variables with no type; `tools/` and `test/` wait too.
- Scripted testing: `window.__outside` (renderer, scene, camera, rig, garden, layout, controls, overlay, fade, vignette, book, textView, backHistory, way, visit, `go`, `enterVR`, `openBook`, `closeBook`, `resetView`, `setAccess(change)`, `access` (the settings and `reduce`), `preview()`, `tick(dt, n)`, `xrDevice`, together, `tv`, `remote`, `stepBack`). `?tv=emulate` is the TV's page in any browser: the arrows, Enter for OK, Escape for Back in the card; `hallwayTV.menu()` and `hallwayTV.back()` stand in for the app's Menu and Back (false: the app would go back a page, `history.back()`). With no XR frames (the app's window not open), VR logic can still be driven while presenting: give `controls.hands[i].source` stand-ins `{ handedness, targetRayMode: 'tracked-pointer', gamepad: { axes, buttons } }` (seven buttons: 3 the thumbstick, 5 B or Y) before each single `tick` (IWER's own sources replace them when it connects them), and set `camera.position.y` (the headset's height) before each, since a render puts the camera back to the XR pose (at the floor, with no frames: open the book after setting it). An XR controller's `matrixAutoUpdate` is off: move or aim one by its `matrix`. A hidden browser pane gets no animation frames, and so no scroll events: drive it with `tick()`, call `textView._rest()` after scrolling the text view, and render a frame before a screenshot (otherwise it shows a stale frame). XR frames under `?xr=emulate` need the pane's tab in front (`tabs_select`); aim with `xrDevice.controllers.right.position/quaternion` (rig-local), `updateButtonValue('trigger', 1)`, `updateAxes('thumbstick', x, y)`. A gamepad: replace `navigator.getGamepads` and dispatch `gamepadconnected`, as in the hallway. A touch: `PointerEvent`s with `pointerType: 'touch'` on the canvas (the pane's own clicks are a mouse's).
- `.claude/launch.json`: `outside` (8090), `outside-quest` (127.0.0.1:8091), and `hallway` (../hallway on 8088) for trying the door both ways.
- Headless Chrome is common's `tools/chrome.mjs` (`launchChrome`, which preview.mjs and hallway-view.mjs use): it writes the fresh profile's `Local State` first so Windows sees no failed logon. Start Chrome for a tool through it, never by hand on a new profile.
- Shared packages, pinned by tag in package.json: AriaMoKr/common (`v0.7.1`: the walking controls (`controls.js`, which the garden's extends), the door contract, `hallway.nav`, the doorway's portal, the fade, the gamepad, the sky, the accessibility settings with the vignette, the book's Back (`back-history.js`), the TV app's remote (`tv.js`), and the tools: `serve.mjs`, `vendor.mjs` with this site's `vendor.json`, `chrome.mjs`, and the Pages workflow `.github/workflows/pages.yml` calls) and AriaMoKr/layersharedsession (`v0.3.0`: the session, the avatars and the session controller). Change them there, then move the tag here and `npm install`; tests that belong to them live there.
- Code still copied from other repos, until it moves into a shared one: `public/js/canvas-panel.js` is vrlbry's `ui/panel.js` Panel cut to buttons, text, sliders and a list without scroll bars (its `set` redraws only on a change, and nothing is allocated over it), and its JSDoc types are its own (vrlbry's has none: `PanelElement`, a `TextElement`, `ButtonElement`, `SliderElement` or `ListElement` of `ListItem`s, and a `Control`, one a pointer can use); `public/js/text-view.js` follows vrlbry's `ui/text-view.js` (its toolbar and markup, its place kept with the 3D book) for this book's parts, with a TV's `turn`, `scrollStep`, `contentsOpen` and `closeContents` added, and JSDoc types of its own (vrlbry's has a few, and no type check); `test/helpers/fake-dom.js` is vrlbry's. A fix to one of them belongs in its original too, and one made there belongs here.
- Link previews: the `og:` and `twitter:` tags in `index.html` show `hallway-preview.jpg`, the picture the hallway's door uses (a test keeps them matching `HALLWAY_DOOR` and the picture's size), so render it again with `tools/preview.mjs` when the garden changes.
